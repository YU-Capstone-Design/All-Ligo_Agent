## 1. 한눈에 보기

- **시연 흐름의 각 구간을 시험했습니다.** AI 생성(시험용 서버), YouTube 업로드(운영 경로), Spring 쪽 연동(로컬 가짜 AI 서버)을 각각 확인했습니다.
- **아직 안 한 것: 운영 종단 시험.** 앱에서 예약해 운영 Spring → AI 서버 → S3 → 결과 수신 → YouTube 업로드까지 실제로 한 번에 이어 보는 시험입니다. 회의 전에 1회 진행할 예정입니다.
- **YouTube 업로드가 다시 됩니다.** 인증 토큰이 만료돼 업로드가 전부 실패하던 문제를 고쳤습니다. 이제 만료 기한이 없는 토큰이고, 운영 경로로 업로드 테스트도 성공했습니다.
- **AI 생성 서버를 안정화했습니다.** 처리 속도, 실패 처리, 보안 문제를 22건 수정했고 자동 테스트 44개를 갖췄습니다.
- **Spring 쪽 연동 문제 9건을 고쳐 운영에 배포했습니다.** PR #55~#59.
- **남은 것은 이번 회의에서 정할 일들입니다.** (아래 2장)

## 2. 회의에서 정할 것

### 2-1. 모두 함께 정할 것

**① 앱에서 생성된 영상을 어떤 링크로 보여줄지**
- 배경: 설계과제 발표에서 교수님이 "만든 영상이 바로 보이게" 하라고 지적하셨습니다.
- 현재: 서버는 두 링크를 이미 모두 앱에 내려주고 있습니다. 앱이 어느 쪽을 재생할지만 정하면 됩니다.

| 선택지 | 볼 수 있는 시점 | 특징 |
|---|---|---|
| A. S3 링크 | 생성 직후 (예약 5분 전) | 가장 빨리 보임. S3 버킷이 영상 공개 읽기를 허용하는지 확인 필요 |
| B. YouTube 링크 | 예약 시각 업로드 이후 | 링크가 있는 사람만 볼 수 있는 "일부 공개" 영상. 재생은 YouTube가 담당 |
| C. 업로드 전엔 S3, 업로드 후엔 YouTube | 생성 직후부터 | 두 장점을 모두 가져감. 앱에서 분기 처리 필요 |

- 제안: **C**. "바로 보이게"라는 요구에 가장 잘 맞습니다.

**② 서버끼리 주고받는 요청에 공유 키(비밀번호) 인증을 붙일지**
- 현재 AI 서버와 Spring의 결과 수신 주소는 인증이 없어서, 주소를 아는 사람이면 누구나 호출할 수 있습니다.
- 특히 Spring의 결과 수신 쪽은 누구나 가짜 결과를 넣을 수 있어 더 급합니다.
- 제안: 발표 전에 시간이 되면 적용합니다. AI 서버 쪽 작업은 작고, Spring 쪽은 헤더 추가와 검사만 하면 됩니다.

**③ AI 생성을 예약 몇 분 전에 요청할지 (운영 값)**
- 현재: 예약 **5분 전**입니다. 코드에는 "테스트 로직"으로 표시돼 있습니다.
- 실측: 영상 1건에 40~90초, 서버가 오래 쉬다가 처음 생성할 때는 최대 약 130초(추정)입니다. 영상 생성은 GPU에서 한 번에 1건씩 처리합니다.
- 제안: **시연은 5분 유지, 운영은 10분.** 다만 "즉시 1회분은 6분 뒤 예약" 로직과 묶여 있어 함께 정해야 합니다.

**④ DB 구조(ERD)가 바뀔 때 AI 서버와 주고받는 항목 공유**
- ERD를 수정 중입니다. 생성 요청과 결과 전달에 쓰는 필드 이름·형식이 바뀌면 **연동 담당에게 먼저 알려 주세요.**

| S3 영상 공개 읽기 | 위 ①에서 S3 링크를 쓰면, 버킷이 영상 공개 읽기를 허용하는지 확인 | 인프라 |

### 2-3. 프론트에서 정할 것 / 확인할 것

| 항목 | 내용 |
|---|---|
| 영상 재생 링크 | 위 ① 결정에 따라 S3 링크(s3VideoUrl) 또는 YouTube 링크(uploadVideoUrl) 재생. C안이면 YouTube 링크가 있으면 그걸, 없으면 S3 |

## 3. 내 담당 진행 현황

### 3-1. AI 생성 서버 (FastAPI)

**운영 상태**
- 연구실 서버에서 상시 구동 중이며, Cloudflare 터널로 외부에 공개돼 있습니다.
- 서버가 시작될 때 필요한 것들(AI 모델, 영상 도구, YouTube 토큰 등)을 스스로 점검하고, YouTube 토큰은 6시간마다 다시 확인합니다.
- 아직 안 된 것: 연구실 서버가 재부팅되면 AI 서버를 수동으로 다시 켜야 합니다. 자동 시작은 설정 예정입니다.

**기능별 상태**

| 기능 | 상태 | 비고 |
|---|---|---|
| 홍보 문구 생성 (게시글/영상 자막) | 정상 | 날씨·과거 우수 게시물·요일 반영 |
| 업로드 사진 분석 | 정상 | 분석 결과 일부가 늘 빠지던 문제 수정 |
| AI 포스터 이미지 생성 (3장) | 정상 | SDXL 모델 사용 |
| 숏폼 영상 제작 (9:16, 나레이션·BGM·자막) | 정상 | 자막 이모지 깨짐 수정 |
| S3 업로드 | 구현됨 · 실제 업로드 미시험 | 일시 실패 시 재시도. 운영 종단 시험 때 확인 예정 |
| 결과 전달 (Spring으로) | 정상 | 실패 시 자동 재시도 3회, 그래도 실패하면 보관 후 재전송 가능 |
| YouTube 업로드 | 정상 | 토큰 재발급 완료(만료 없음), 같은 영상 중복 업로드 방지 |

**오늘 고친 것 (22건)**
- 속도·멈춤
  - 생성하는 동안 서버가 다른 요청에 응답하지 못하던 문제 해결
  - 게시글 문구 생성 시간 단축: 최대 3분 18초 → 약 4~6초 (AI의 "생각하기" 모드를 끔)
  - 영상용 이미지 3장 생성 시 AI 모델을 한 번만 불러오도록 개선 (3번 불러오던 것을 1번으로: 로딩 약 141초 → 47초)
  - 여러 요청이 동시에 와도 GPU 메모리 부족으로 같이 실패하지 않게 순서대로 처리
- 실패 처리
  - Spring이 잠깐 꺼져 있어도 결과가 사라지지 않음 (자동 재시도 + 보관 + 재전송 도구)
  - 영상 요청인데 영상을 못 만들면: 업로드 사진으로 대신 만들고, 그것도 안 되면 "실패"로 통보 (예전엔 영상 없이 "성공"으로 보냄)
  - AI가 빈 문구를 내거나 이미지 설명을 빠뜨리면 한 번 더 생성
  - 과거 게시물에 중괄호 같은 특수문자가 있으면 생성이 실패하던 문제 수정
- 품질
  - 업로드 사진 분석에서 가장 중요한 "사물" 키워드가 늘 빠지던 문제 수정
  - 영상 자막에 이모지가 네모(□)로 찍히던 문제 수정
  - 영문 요일(MONDAY)을 한글로 바꿔 문구에 반영
- 안전
  - 서버 안의 아무 영상이나 YouTube로 올릴 수 있던 경로 제한
  - 잘못된 이미지 주소(이미지가 아님, 20MB 초과 등)는 요청 단계에서 바로 거절
  - 같은 영상이 YouTube에 두 번 올라가지 않게 방지
- 운영
  - 서버 상태 점검 화면 추가 (/api/system/preflight)
  - YouTube 토큰 만료를 미리 알리는 기능 추가 (만료 기한 경고 + 6시간 주기 점검)
  - 개인정보처리방침 페이지 추가 (Google 앱 게시에 필요)
  - 자동 테스트 44개 (외부 서비스 없이 3초 안에 실행)

**YouTube 업로드 복구 과정**
- 원인: Google 앱 설정이 "테스트" 상태여서 인증 토큰이 7일마다 만료됐습니다.
- 조치: 앱을 "프로덕션"으로 게시한 뒤 토큰을 재발급해 이제 만료 기한이 없습니다. 업로드 테스트도 성공했습니다.
- 업로드 한도: 하루 100건, 무료입니다.

**실측 성능**

| 작업 | 시간 |
|---|---|
| 게시글(POST) 생성 | 약 6초 (업로드 사진 분석 포함 시 더 걸림) |
| 영상(VIDEO) 생성 1건 | 약 40~90초 |
| 서버가 오래 쉬다가 첫 영상 생성 | 최대 약 130초 (추정) |
| 영상 2건 동시 요청 | 2건 합계 약 54초 |
| YouTube 업로드 (영상 13MB) | 약 3초 |

## 4. 참고: 전체 흐름

```
[앱] 홍보 예약
   ↓
[Spring] 예약 5분 전 → AI 서버에 생성 요청
   ↓
[AI 서버] 문구 생성 → (영상이면) 이미지 3장 → 영상 제작 → S3 업로드
   ↓
[AI 서버 → Spring] 결과 전달 (실패 시 자동 재시도)
   ↓
[Spring] 콘텐츠 저장 · 알림 · 대기열 "생성 완료"
   ↓
[Spring] 예약 시각 → AI 서버에 YouTube 업로드 요청 (실패 시 10분간 재시도)
   ↓
[앱] 영상 확인 (S3 링크 또는 YouTube 링크 — 회의 ①)
```
