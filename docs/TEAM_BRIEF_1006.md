## 1부. 내가 한 것 (보고)

담당: AI 생성 서버(FastAPI) 전체 + Spring의 "예약 → AI 생성 요청 → 결과 수신 → YouTube 업로드" 파이프라인

**1. YouTube 업로드 복구**
- 인증 토큰이 만료돼 업로드가 전부 실패하고 있었습니다.
- 원인은 Google 앱 설정이 "테스트" 상태라 토큰이 7일마다 만료되는 것이었습니다.
- 앱을 "프로덕션"으로 게시하고 재발급해 이제 만료가 없습니다. 운영 업로드 테스트도 성공했습니다.

**2. AI 생성 서버 안정화 (코드 수정 22건)**
- 속도: 게시글 문구 생성 최대 3분 18초 → 약 4~6초, 영상용 이미지 모델 로딩 약 141초 → 47초
- 실패 처리: Spring이 잠깐 꺼져도 결과가 사라지지 않음(자동 재시도·보관), 영상 생성 실패 시 "성공"으로 잘못 알리던 문제 수정
- 품질: 사진 분석 키워드 누락, 영상 자막 이모지 깨짐 수정
- 안전: 아무 영상이나 YouTube로 올릴 수 있던 경로 차단, 같은 영상 중복 업로드 방지
- 자동 테스트 44개, 서버 상태 점검 기능 추가

**3. Spring 업로드 파이프라인 수정 (PR #55~#59, 운영 배포 완료)**
- S3 업로드만 실패해도 영상이 YouTube에 안 올라가던 문제 수정
- 취소한 콘텐츠가 예약 시각에 업로드되던 문제 수정
- 대기열이 "생성 중"에서 멈추던 문제 수정
- 업로드 실패 시 10분간 재시도, 놓친 예약 복구
- 날씨 반영을 켠 홍보에만 매장 위치 전송

### 1. 앱에서 영상을 어떤 링크로 보여줄지
- 배경: 설계과제 발표에서 교수님이 "만든 영상이 바로 보이게" 하라고 지적하셨습니다.
- 서버는 두 링크를 이미 모두 앱에 내려주고 있어서, 앱이 어느 쪽을 재생할지만 정하면 됩니다.

| 선택지 | 볼 수 있는 시점 | 특징 |
|---|---|---|
| A. S3 링크 | 생성 직후 (예약 5분 전) | 가장 빠름. S3 버킷이 영상 공개 읽기를 허용하는지 확인 필요 |
| B. YouTube 링크 | 예약 시각 업로드 이후 | 링크가 있는 사람만 보는 "일부 공개" 영상 |
| C. 업로드 전엔 S3, 후엔 YouTube | 생성 직후부터 | 둘의 장점을 모두 가져감. 앱에서 분기 필요 |

### 2. 같은 계정의 같은 시각 예약 막기 (필수)
- 지금은 한 홍보 안에서만 중복을 막고, 같은 계정의 **다른 홍보끼리는** 같은 시각 예약이 가능합니다.
- AI 서버는 영상을 한 번에 1건씩 만들어서, 같은 시각에 몰리면 뒤 순번이 늦어질 수 있습니다.
- 정할 것: 어느 화면·API에서 막을지, 오류 메시지, 담당. 다른 계정끼리 겹치는 문제는 이번엔 제외합니다.

### 3. AI 생성을 예약 몇 분 전에 요청할지
- 현재는 5분 전입니다. 코드에는 "테스트 로직"으로 표시돼 있습니다.
- 영상 1건에 40~90초, 서버가 오래 쉬다가 처음 만들 때는 최대 약 130초(추정) 걸립니다.
- "즉시 1회분은 6분 뒤 예약" 로직과 묶여 있어 함께 정해야 합니다.

### 4. 서버끼리 요청에 공유 키 인증
- 지금은 AI 서버와 Spring의 결과 수신 주소 모두 인증이 없어, 주소를 아는 사람이면 누구나 호출할 수 있습니다.
- 특히 결과 수신 쪽은 누구나 가짜 결과를 넣을 수 있어 더 급합니다.

### 5. DB 구조(ERD) 변경 시 연동 필드 공유
- ERD를 수정 중입니다. AI 서버와 주고받는 필드 이름·형식이 바뀌면 연동 담당에게 먼저 알려 주세요.

### 6. 백엔드 정리 항목

| 항목 | 내용 |
|---|---|
| 운영 DB 설정 | 자동 스키마 변경(ddl-auto: update) 유지 여부, 외래키 삭제 규칙 운영 적용 확인 |
| 헬스 체크 | GET /health 가 로그인을 요구(403). 헬스 체크용이면 공개로 |
| 로그아웃 | 로그아웃해도 토큰이 폐기되지 않음 |
| 콘텐츠 만료 | 만료 상태(EXPIRED)·만료 시각(expiresAt)이 정의만 되고 안 쓰임 |
| 보안 설정 정리 | 삭제된 /api/v1/fastapi/* 경로의 공개 설정이 남아 있음 |
| 없는 주소 응답 | 없는 주소에 404 대신 500을 줌 |
| S3 영상 공개 읽기 | 안건 1에서 S3 링크를 쓰면 버킷 설정 확인 |
